# Domain Docs

Single-context: one `GLOSSARY.md` and `docs/adr/` at the repo root.

- **Before exploring**, read `GLOSSARY.md` and the ADRs in `docs/adr/` that touch the area you're about to work in.
- **Name domain concepts with the glossary's terms** in issue titles, refactor proposals, hypotheses and test names. A concept the glossary lacks is either language the project doesn't use (reconsider) or a real gap (note it for `/domain-modeling`).
- **Flag ADR conflicts** explicitly when your output contradicts one: _"Contradicts ADR-0007 (event-sourced orders), but worth reopening because…"_
